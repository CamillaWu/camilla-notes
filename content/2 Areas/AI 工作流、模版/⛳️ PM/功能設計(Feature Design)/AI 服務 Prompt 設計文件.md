## 使用場景

適用於設計和記錄產品中 AI 模型或生成式服務的提示詞 (prompt) 方案。當團隊開發 AI 驅動的功能（例如聊天機器人、自動內容生成工具等）時，需要詳細說明該功能的提示詞設計、上下文來源及性能考量。本模板有助於團隊在引入 AI 功能時明確設計思路與實現細節。

## Prompt

```markdown
請扮演一位熟悉大型語言模型應用的產品經理，為我們的 **AI 服務功能 Prompt 設計文件** 撰寫內容。請以 Markdown 格式組織，說明這個 AI 功能的提示設計與相關細節，包含以下章節：

1. **功能概述**：簡要描述該 AI 功能的目的和作用。例如：「此功能為用戶提供智能客服回答，透過 NLP 模型即時解答理財問題。」說明這項功能解決的用戶痛點，以及它在產品中的定位。

2. **Prompt 設計目標**：闡明我們希望透過 prompt 達成的目標。包括希望模型輸出的風格或準確性要求，例如「提供專業且簡潔的回答」，以及需要避免的行為（如避免提供法律建議等）。明確此 prompt 在模型中的角色定位（如讓模型扮演專家顧問等）。

3. **提示詞內容與結構**：列出目前設計的 prompt 內容或模板。說明 prompt 是如何編寫的，包括：
   - **系統提示 (System Instruction)**：模型的初始設定，如角色設定或語調要求。
   - **用戶提問格式**：如果有特定的輸入格式或關鍵字需要模型識別，予以說明。
   - **示例對話或 Few-shot 訓練**：如有提供模型參考的範例問答，列舉這些示例以示範模型應如何回應。
   請使用縮進或程式碼區塊呈現實際的 prompt 文本範例，並在其中用註解標註關鍵部分或變數（例如用 `<變數>` 表示動態內容）。

4. **上下文與資料來源**：說明模型在生成回答時可取用的上下文資訊來源。例如：「結合後端知識庫檢索 (RAG) 技術：模型在回答前會查詢我們的FAQ資料庫，以提取相關內容。」列出外部資料來源或API，及它們如何與 prompt 結合（例如將檢索結果附加在 prompt 中）。確保團隊了解模型回答所依賴的資訊範圍，以便評估回答可靠性。

5. **質量評估與調優**：定義如何評估此 prompt 的效果。包括衡量模型回覆品質的指標（例如正確率、用戶滿意度、回答長度控制等），以及測試用例。說明目前已進行或計劃進行的調優措施，例如微調 (fine-tuning) 訓練、Prompt 試錯調整、溫度/Top-p 等參數設定。列出發現的問題案例以及對應的優化策略（如修改提示詞措辭，增加範例等）。

6. **風險與限制**：列出該 AI 提示方案可能存在的局限或風險，包括：
   - **誤答風險**：模型可能出錯的類型（例如錯誤資訊、偏見內容）以及如何減輕（如增加過濾機制）。
   - **資源消耗**：對計算資源或API調用成本的影響，以及流量增長後的應對方案（如緩存機制）。
   - **法規合規**：模型回答可能涉及的法律/合規風險（如隱私洩漏），以及對策（如對敏感資訊不作答等）。
   說明團隊對這些風險的認知和預防措施。

7. **未來優化方向**：簡述未來可改進的方向。例如考慮引入更大型的模型、增加多語言支持、引入用戶反饋機制持續訓練模型等。讓團隊對該 AI 功能的長期演進有基本認識。

請將以上內容彙整成完整的 AI 服務 Prompt 設計文件，確保技術與非技術成員都能讀懂。我將提供相關背景資訊供你參考。請特別注意語氣專業、內容詳實。
<在此提供AI功能的描述、當前Prompt草案、及任何技術細節，供AI生成文檔>

```
