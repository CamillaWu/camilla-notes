## Key Points

> [!summary] 選型一句話
> **要邏輯與文字 → 自迴歸｜要高品質創意圖/影片 → 擴散｜要即時低延遲 → GAN｜要壓縮、異常檢測、視覺 Token → VAE｜要精確機率、科學模擬 → Flow / EBM**

#### 五大家族總比較

| 模型 | 核心機制（比喻） | 損失函數 | 生成速度 | 代表模型 | 最佳場景 | 致命痛點 |
|---|---|---|---|---|---|---|
| **自迴歸 AR** | 逐 Token 接龍（打字機） | 交叉熵 | 慢（逐字） | GPT、Llama、Claude | 對話、寫作、程式碼 | 幻覺、誤差累積、KV Cache 成本 |
| **VAE** | 壓縮成機率分佈再抽樣還原 | 重建損失 + KL 散度 | 快（一次前向） | VAE、β-VAE、VQ-VAE | 異常檢測、降維、視覺 Tokenizer | 圖像模糊、Posterior Collapse |
| **擴散 Diffusion** | 加噪 → 逐步去噪（洗毛玻璃） | 噪聲預測誤差（MSE） | 慢（多步去噪） | Stable Diffusion、Flux、Sora | 文生圖/影片、局部重繪 | 延遲高、文字渲染差（新版已改善） |
| **GAN** | 生成器 vs 判別器對抗（偽鈔 vs 鑑定師） | Minimax | 極快（一次前向） | StyleGAN、CycleGAN、SRGAN | 即時濾鏡、超解析度、風格轉換 | 訓練不穩、Mode Collapse |
| **Flow / EBM** | 可逆變換（黏土）/ 能量函數（重力） | 負對數似然 NLL | 視架構而定 | Glow、RealNVP、Flow Matching | 科學模擬、音訊、異常檢測 | 數學門檻高、成本高 |

#### 依「數據特性 × 問題需求」選型

| 數據特性 / 需求 | 首選 | 理由 |
|---|---|---|
| 文字、序列、需上下文推理 | 自迴歸 | 鏈式法則天生適合序列 |
| 高品質圖像/影片、用文字描述生成 | 擴散（DiT） | 品質與多樣性最佳、聽得懂長提示 |
| 即時互動、手機端、低延遲 | GAN／蒸餾後的擴散（LCM） | 一次前向即出圖 |
| 只有正常樣本、要抓異常 | VAE（重建誤差）／Flow（似然值） | 異常資料重建不好或機率極低 |
| 不容幻覺、需精確機率 | Flow／EBM | 有數學保證的機率估計 |
| 圖像要接到 LLM 處理 | VQ-VAE（離散 Token） | 把圖「文字化」 |
| 資料少、預算有限 | 遷移學習 + 微調現成模型 | 不要從頭訓練 → [[訓練模型與如何優化]] |

#### 控制參數對照（常考）

| 模型 | 控制旋鈕 |
|---|---|
| 自迴歸 | Temperature、Top-P、Top-K、重複懲罰 |
| 擴散 | CFG Scale（聽話程度）、Inference Steps（去噪步數）、Seed |
| GAN | 潛在向量操控、條件式 cGAN（類別標籤） |
| VAE | 潛在空間解耦（β-VAE）、離散碼本（VQ-VAE） |

#### 崩潰名詞配對（陷阱題）
- **Mode Collapse（模式崩潰）** → GAN：只會重複生成同一種樣本
- **Posterior / Latent Collapse（潛在空間崩潰）** → VAE：解碼器忽略潛在變數，只吐模糊平均圖
- **幻覺 + 誤差累積** → 自迴歸：前一步錯，後面全錯

## Notes

### 一、五大生成模型家族

#### 1. 自迴歸模型 (Autoregressive Models, AR)
##### 骨架架構與核心運作原理
###### 核心數學基石：機率鏈式法則
- 自迴歸模型本質上是在==做**序列的機率預測**==。
- **預測機制**：模型每次只生成一個單位。
- **輸入依賴**：下一步的輸入包含過去所有已生成的內容。
- **打字機效應**：文字像打字機一樣一個個跳出。
- **數學基礎**：將聯合機率拆解為條件機率的乘積。
###### 傳統骨架：基於 RNN / LSTM / GRU 的循環網路
- **代表模型**：早期的 Google 翻譯、基於 WaveNet 的語音合成、Char-RNN。
- **運作結構**：使用**循環神經網路（RNN）** 及其變體 LSTM（長短期記憶網路）。
- **結構特性**：
    - **串行記憶傳遞**：網路內建一個「隱藏狀態（Hidden State）」，像傳話遊戲一樣，讀取第 1 個字，更新狀態，再讀第 2 個字……。
    - **遺忘與梯度消失**：因為資訊必須沿著時間軸一步步傳遞，當句子太長（例如超過 100 個字），前面字的特徵在不斷乘以權重後會徹底消失，導致模型「讀到後面，忘了前面」。
###### 新版骨架：基於 Transformer (Decoder-Only) 的自注意力網路
- **代表模型**：**GPT 家族（GPT-4o, ChatGPT）**、Llama 3、Claude 3.5。
- **運作結構**：完全捨棄循環結構，改用 **Transformer 的解碼器（Decoder）** 作為骨架。
- **結構特性**：
    - **全局自注意力機制（Self-Attention）**：取消了「步步傳遞」的限制，所有字一次性輸入。模型透過計算矩陣，讓序列中的任何一個字都能直接與其他所有字建立聯繫。只要在上下文視窗內，相隔很遠的字也能直接建立關聯（但超長文本中段的資訊仍可能被忽略，稱為「Lost in the Middle」）。
    - **遮罩技術（Causal Masking）**：為了維持自迴歸的特性，新骨架在矩陣中加入遮罩，強迫模型在計算第 $N$ 個字時，把第 $N+1$ 個字以後的權重通通歸零，實現「==能看清過去所有細節，但絕不偷看未來==」的運作。
##### 創造性（Creativity）與控制能力（Generation Control）
- 自迴歸模型（如 GPT 家族）在「創造性」與「精確度」的拿捏上，完全取決於**推論階段（Inference）對「下一個 Token 的機率分佈抽樣」之控制**。
1. 創造性（隨機性）的來源
	自迴歸模型輸出時，最後一層會吐出一個包含數萬個詞彙的機率分佈（Logits），並透過 **Softmax** 函數標準化。如果每次都只選機率最高的第一名（稱為 Greedy Decoding），模型的回答會變得極度呆板、重複。為了釋放**創造性**，必須引入隨機抽樣。
2. 控制能力的四大核心參數
	* **溫度參數 (Temperature, $T$)**
	    * **原理**：調整計算法則為：
	        $$P(x_i) = \frac{\exp(z_i / T)}{\sum_{j} \exp(z_j / T)}$$
	    * **低溫度（如 0.2）**：使機率最高的詞更明顯，其餘趨近於 0。模型輸出極度**精確、穩定、公式化**。適合寫程式、計算、回答事實。
	    * **高溫度（如 0.9 或 1.2）**：平滑機率分佈，讓原本低機率的詞有機會被選中。模型展現出極高的**創造性、想像力**，但代價是容易出現「幻覺（Hallucination）」。
	- **Top-P (核抽樣, Nucleus Sampling)**
	    - **原理**：設定一個累積機率門檻（例如 0.9）。模型會把候選詞按機率從大到小排序，只在累積機率加總達到 90% 的「核心詞池」中進行抽樣，徹底切除後面 10% 沒邏輯的廢詞。
	- **Top-K**
	    - **原理**：強制模型只能在機率最高的前 $K$ 個詞（例如 $K=50$）中進行抽樣，直接限制候選數量。
	- **重複懲罰 (Frequency/Presence Penalty)**
	    - **原理**：當一個詞在前面已經生成過，模型會人為降低它在下一步的機率值，**防止自迴歸模型陷入自我重複的死循環**。
##### 提示工程（Prompt Engineering）與輸入優化深度
- **脈絡關聯的定調**：自迴歸模型是「基於歷史預測未來」。如果你給的開頭（Prompt）邏輯嚴密、結構清晰，模型在數學條件機率上，就更容易收斂到高質量的輸出區間。
- **思維鏈（Chain-of-Thought, CoT）**：自迴歸模型每一步只能消耗固定的算力去猜下一個字。如果你要求它直接給答案，它很容易猜錯；但如果提示詞要求它「一步步思考」，模型就可以把複雜問題拆解，**利用前面吐出的思考步驟（作為新的歷史輸入）來幫助後面計算出正確答案**。
- **傳統自迴歸骨架的限制**：不支援複雜的提示工程。舊版 RNN/LSTM 的記憶力隨距離衰減，給它太長的 Prompt 或 Few-shot 範例，模型還沒開始生成，前面的提示詞就已經在隱藏狀態（Hidden State）中被覆寫遺忘了。
- **新版自迴歸骨架的優勢**：提示工程的黃金搭檔。現代 Transformer 解碼器擁有海量的上下文視窗（Context Window），利用全局注意力機制，強迫模型在生成每一個 Token 時，都能死死盯著 System Prompt 設定的角色與嚴格規則。
##### 架構複雜度與硬體代價：平行訓練 vs 串行推論
- **簡單生成任務（輕量級自迴歸模型，如 1B ~ 8B 參數）**：
    - **代表模型**：Llama-3-8B、Gemma-7B。
    - **硬體要求**：可部署於單張消費級顯示卡（如 RTX 4090）或邊緣設備（手機/筆電端）。
    - **適用場景**：文本分類、特定格式的摘要、結構化資料提取（JSON 轉換）、意圖識別、簡單的自動回覆客服。
    - **設計優勢**：推論速度快（Time-to-First-Token 短），部署成本與 API 費用極低，適合高併發的簡單產品任務。
- **複雜應用需求（高效能自迴歸模型，如 70B ~ MoE 混合專家架構）**：
    - **代表模型**：GPT、Claude、Gemini 等旗艦模型（閉源，架構細節未完全公開），以及開源的 Llama 3 70B、DeepSeek-V3（MoE）。
    - **硬體要求**：需要多卡並行（Tensor Parallelism），極度依賴 H100/H200 等資料中心級 GPU 集群。
    - **適用場景**：跨領域複雜邏輯推理、代碼庫級別編寫、法律/醫療專家系統、長文本多輪對話。
    - **設計策略**：常採用 **MoE（Mixture of Experts）架構**，雖然總參數極大，但每次推論只激活部分專家網路，在維持大模型高效能推理的同時，兼顧 Token 的生成速度。
- **推論階段的代價（KV Cache）**：新版骨架雖然訓練快，但推論時因為要不斷回頭看過去所有字的 Attention 特徵，硬體記憶體（VRAM）消耗極大。因此，現代架構設計必須引入 **KV Cache（鍵值快取）** 技術，並普遍採用 **GQA（分組查詢注意力）** 來精簡 KV Cache（大小模型都在用，例如 Llama 3 8B 與 70B）。
##### 訓練階段與超參數設置
- **損失函數（Loss Function - Cross Entropy）**：自迴歸模型使用**交叉熵損失**。在訓練的每一格（Token Position），模型預測下一個字的機率分佈，與真實文本的 One-hot 編碼（正確答案為 1，其餘為 0）計算差距。總損失是整個序列所有 Token 損失的平均值。
- **訓練批次大小（Batch Size）與週期數（Epochs）**：
    - 自迴歸大模型通常採用**極大的 Batch Size**（透過數據並行達數百萬個 Token/Batch），配合梯度累積（Gradient Accumulation），這能確保在海量文本訓練時的梯度方向足夠穩定。
    - 為了防止模型對特定文本死記硬背（過擬合），現代 LLM 進行預訓練時，通常只跑 **1 到 2 個 Epochs**。因為網路上的數據極多，讓模型「博覽群書各看一次」，比「死背一本書看很多次」更能建立強大的泛化能力。
- **學習率（Learning Rate）與超參數調整**：
    - 自迴歸 Transformer 的訓練非常脆弱，容易發生梯度爆炸。因此通常採用 **Cosine Annealing（餘弦退火）** 學習率策略，並搭配 **Warmup（預熱階段）**，在訓練初期緩慢提升學習率，中後期再逐步降至接近 0。
- **過擬合防範（Overfitting）**：
    - **自迴歸模型（LLM）的防禦機制**：
        - 主要依賴**極其龐大且多樣化的數據集（Data Diversity）**與**權重衰減（Weight Decay）**（大型 LLM 預訓練多半不開 Dropout）。因為資料量大到模型一輩子看不完，它根本沒機會死記硬背。
##### 適用場景與限制
###### 最佳適用場景
自迴歸模型在 **「邏輯連貫性、上下文推理、結構化序列」** 的任務上具有絕對優勢
- **高階邏輯推理與日常對話**：
    - **場景**：智慧客服、AI 法律/醫療助理、複雜的決策支援系統。
    - **原因**：因為它嚴格遵守「機率鏈式法則」，每一步都基於過去的所有歷史，最擅長維持長文本的邏輯不跳針。
- **文本創作與創意寫作**：
    - **場景**：文章摘要、廣告文案生成、小說續寫、Email 撰寫。
    - **原因**：配合**溫度參數（Temperature）**與 **Top-P** 的動態調配，能完美兼顧故事流暢度與出人意料的創意。
- **精準結構化代碼生成**：
    - **場景**：GitHub Copilot、自動化寫 Code、SQL 語法生成、JSON 格式資料提取。
    - **原因**：程式碼是極度依賴前言後語的序列，自迴歸的「接龍」特性完美契合代碼語法。
###### 核心技術限制與痛點
- **推論延遲高（Auto-regressive Bottleneck）**：
    - **痛點**：因為必須嚴格「逐字（Token）生成」，無法像其他模型（如 VAE/GAN）那樣一瞬間輸出整張圖或整段話。
    - **PM 的 UX 解法**：這就是為什麼 ChatGPT 必須設計成 **「打字機動畫」** 吐字。這不是為了解悶，而是為了掩蓋自迴歸模型推論過慢的底層硬體限制。
- **自戀與幻覺（Hallucination）與誤差累積（Error Propagation）**：
    - **痛點**：自迴歸是「拿自己剛猜完的字，當作下一步的絕對正確背景」。如果中間有一步猜錯或開始胡言亂語（幻覺），這個錯誤就可能一路放大，導致後面整段內容全盤崩潰。
    - **PM 的產品解法**：在產品介面必須加上「AI 生成內容僅供參考」的免責聲明，或者引入 **RAG（檢索增強生成）** 技術，強迫模型在鏈式推理時必須對齊外部真實資料庫。
- **驚人的記憶體（VRAM）與算力成本**：
    - **痛點**：隨著對話變長，鏈式法則的歷史包袱會越來越重。模型為了記住前面的話，必須維護龐大的 **KV Cache（鍵值快取）**，這會吃掉海量的伺服器顯示記憶體，導致用戶量大時伺服器成本（API Cost）直線飆升。

#### 2. 變分自編碼器 (Variational Autoencoders, VAEs)

##### 骨架架構與核心運作原理
###### 核心數學基石：潛在空間的機率分佈映射
- 變分自編碼器本質上是在做**數據的強效壓縮與連續性解碼還原**。
- **預測機制**：模型不是直接複製輸入，而是將輸入數據（如影像）壓縮成一個低維度的**潛在空間（Latent Space）**。
- **機率本質**：
	- 傳統 AE（Autoencoder）只把圖變成一個固定的連續數值向量（容易導致生成斷層）。
		- 就像一個 **「無情的拉鍊壓縮軟體 (WinRAR)」** 。它把一張 10MB 的大圖，死板地壓縮成一個 10KB 的代碼檔案。解壓縮時，它只能還原一模一樣的圖。如果你隨便改動壓縮檔裡的一個字元，解壓出來的圖就會直接壞軌、變成亂碼。
	- VAE 則是讓編碼器去預測一個**機率分佈（平均值 $\mu$ 與標準差 $\sigma$）**，解碼器再從這個分佈中「抽樣」來重建數據。
		- 這才是真正的「生成式 AI」。它不存死板的硬資料，而是去存 **「特徵的機率區間（例如：眼睛大小的範圍、膚色的區間）」** 。這讓它在生成時，可以隨機在這個區間內「抽樣」，從而能創造出「全新、沒看過的人臉」。
- **數學基礎**：透過最大化**證據下界（ELBO, Evidence Lower Bound）**，在「重建精確度」與「潛在空間平滑度」之間取得數學平衡。
	- 潛在空間 (Latent Space)→產品經理叫它：**「特徵秘密基地」**
	- 證據下界 (ELBO)→產品經理叫它：**「平衡分數」**（讓模型在「畫得像不像」與「特徵基地好不好管理」之間取得平衡）。
###### 傳統骨架：基於 MLP / CNN 的對稱網路
- **代表模型**：標準 VAE、Conditional VAE (CVAE)、$\beta$-VAE。
- **運作結構**：使用**全連接層（MLP）** 或**卷積神經網路（CNN）** 構成。拿一個放大鏡，在照片上從左到右、從上到下一格格掃描。
- **結構特性**：看圖流派（見樹不見林）
    - **鏡像對稱性**：編碼器（Encoder）與解碼器（Decoder）通常結構對稱。編碼器透過逐層卷積壓縮特徵，解碼器透過轉置卷積（Deconvolution）放大還原。
    - **局部特徵局限**：傳統 CNN 骨架==只能捕捉畫面上的局部特徵==（如邊緣、紋理），缺乏對整張圖像全局宏觀語意的理解，==導致生成的影像邊緣容易**模糊==（Blurry）**。
###### 新版骨架：離散化的 VQ-VAE / VQ-GAN（視覺 Tokenizer 時代）
- **代表模型**：VQ-VAE、VQ-VAE-2、VQ-GAN、ViT-VQGAN（現代多模態大模型的視覺 Tokenizer）。
- **運作結構**：保留「編碼器 → 潛在空間 → 解碼器」的骨架，但把連續的潛在向量換成**離散碼本（Codebook）**。編碼器輸出的每一塊特徵，都會替換成碼本中最接近的「代碼」。
- **結構特性**：
    - **影像文字化**：一張圖變成一串離散代碼，就像一句話變成一串 Token，可以直接交給 Transformer / LLM 處理。
    - **解決模糊**：VQ-GAN 額外加入 GAN 判別器與感知損失（Perceptual Loss），重建影像明顯比傳統 VAE 銳利。
    - **骨架演進**：原版 VQ-VAE、VQ-GAN 的編碼器仍以 **CNN** 為主；**ViT-VQGAN** 才改用 Vision Transformer。
    - **Stable Diffusion 裡的 VAE**：Stable Diffusion 先用 VAE 把圖片壓到潛在空間，再在潛在空間裡去噪（Latent Diffusion），這是 VAE 在現代最大量的應用之一。

> [!note] 延伸：MAE（遮罩自編碼器）≠ VAE
> - **MAE（Masked Autoencoders，Meta 2021）** 是**自監督表徵學習**方法，以 ViT 為骨架：把圖片切成 Patches，**隨機遮蔽 75%**，重量級編碼器只看剩下 25%，輕量解碼器負責補回被遮的像素。
> - 它**沒有 KL 散度、不從機率分佈抽樣**，目的不是生成新圖，而是訓練出「看得懂圖」的視覺編碼器，再拿去做分類、偵測等下游任務。
> - MAE 補回來的畫面其實**偏模糊**（只用 MSE 損失），語意結構大致正確；它的價值在學到的特徵，不在畫質。
> - **遮罩率**：太低（約 20%）時，模型抄鄰近像素就能還原，學不到語意；**約 75%** 效果最好。
> - **損失函數**：只對**被遮蔽的 Patches** 計算 MSE。
> - **防過擬合**：每次隨機遮罩，等於無限種資料增強，天然具防過擬合效果。

##### 創造性（Creativity）與控制能力（Generation Control）
- VAE 家族在創造力與控制力的表現上，取決於其**潛在空間（Latent Space）是否成功「解耦（Disentanglement）」與「數位離散化」**。
###### (1) 創造性（隨機性）的來源
- 傳統 VAE 透過在連續的標準常態分佈中隨機採樣一個向量（Latent Vector），投餵給解碼器來生成新數據。但因為骨架和連續分佈的限制，其創造出的新影像細節模糊，缺乏高清晰度的創意爆發力。
- 新版 VQ-VAE / VQ-GAN 把圖片轉成離散代碼，再由後端的自迴歸 Transformer 或擴散模型「重新組合代碼」來生成新圖。VQ-GAN 加入對抗損失後，畫面比傳統 VAE 清晰許多。
###### (2) 控制能力的兩大核心機制
- **潛在空間特徵解耦（連續控制 - 傳統骨架）**
    - **原理**：透過引入超參數調控（如 $\beta$-VAE），可以將潛在空間的某一個特定維度與現實特徵鎖定。
    - **表現**：調整特定維度的數值，就能直接、平滑地控制生成人臉的「旋轉角度」或「微笑程度」。
- **離散碼本（離散控制 - 新版骨架）**
    - **原理**：將圖像壓縮成一串數位索引（類似字典裡的單字碼），建立**離散碼本（Discrete Codebook）**。
    - **表現**：將視覺資訊徹底「文字化」，這讓它能完美無縫地對接後續的自迴歸大語言模型（LLM）或擴散模型（Diffusion），進行極度精細的文字條件（Text Prompt）生成控制。

##### 提示工程（Prompt Engineering）與輸入優化深度
- **傳統自編碼器骨架**：**不支援文字提示詞（Prompt）**。其輸入是「完整的真實數據（圖像/音訊）」。它的優化主要依賴**數據增強（Data Augmentation）** 或在輸入中人為加入噪點（如 DAE），強迫模型學習去噪。
- **新版骨架（VQ-VAE / VQ-GAN）**：本身仍不直接吃文字提示詞；但因為它把圖片變成離散 Token，後端的 LLM 或擴散模型就能用文字 Prompt 控制要生成哪些代碼。（MAE 的遮罩率設定見上方「延伸」說明。）

##### 架構複雜度與硬體代價：平行訓練 vs 視覺 Tokenizer
- **簡單生成任務（傳統/輕量級，如舊版 CNN-VAE）**：
    - **硬體要求**：硬體要求極低，在單張消費級顯卡或邊緣端設備即可高效運行。
    - **適用場景**：工業產線上的缺陷異常檢測（Anomaly Detection）、醫療影像的去噪與初步壓縮、結構化資料降維。
    - **設計優勢**：推論速度極快，因為解碼器只需做一次前向傳播（Forward Pass）即可**一次性輸出整張圖**（不像自迴歸模型需要排隊打字）。
- **複雜應用需求（高效能/基於 Transformer 的前處理骨架）**：
    - **代表模型**：VQ-VAE-2、VQ-GAN。
    - **硬體要求**：Tokenizer 本身不算大，但需要大量影像與資料中心級 GPU 訓練；真正昂貴的是後端接手生成的大模型。
    - **適用場景**：現代多模態大廠的核心視覺基礎建設。
    - **設計策略**：現代大廠不再單獨用 VAE 來直接生成最終大圖，而是多將其作為大型多模態模型的 **「視覺代碼化（Tokenizer）前處理骨架」**（例如第一代 DALL-E 的 dVAE、Meta 的 Chameleon；Stable Diffusion 也用 VAE 把圖片壓到潛在空間再去噪）。先用 VAE 將圖片轉成離散 Token，再交給後面的高效能模型發揮。

##### 訓練階段與超參數設置
- **損失函數（Loss Function - Reconstruction & KL）**：
    - **傳統 VAE**：採用極其複雜的兩部分損失——**重建損失（Reconstruction Loss，如 MSE）** 加上 **KL 散度（KL Divergence）**。
        $$Loss = \text{Reconstruction Loss} + \beta \times \text{KL Divergence}$$
    - **超參數失衡硬傷**：KL 散度用來約束潛在空間的分佈。如果 KL 權重太強（或解碼器太強），編碼器會放棄傳遞資訊、潛在變數形同虛設，解碼器只吐出模糊的平均圖（學術名稱 **Posterior Collapse**，常譯「潛在空間崩潰」）。
- **過擬合防範（Overfitting）**：
    - **傳統 VAE 防禦機制**：依賴 KL 散度加入的隨機噪聲，以及傳統的交叉驗證（Cross Validation）與網格搜索（Grid Search）。

##### 適用場景與限制
###### 最佳適用場景
變分自編碼器在 **「數據降維、特徵解耦控制、多模態 Token 化前處理」** 的任務上具有絕對優勢：
- **工業與安全異常檢測（Anomaly Detection）**：
    - **場景**：半導體晶圓瑕疵檢測、信用卡盜刷行為分析。
    - **原因**：模型用正常數據訓練後，如果輸入異常數據，其「重建損失（MSE）」會飆高，PM 即可以此建立極其精準的警報系統。
- **多模態視覺代碼化（Vision Tokenizer）**：
    - **場景**：多模態 LLM（如理解圖片的 AI 助理）的底層視覺輸入端。
    - **原因**：利用新版 VQ-VAE 骨架，將連續的影像像素完美轉換為離散的數位 Token，打通「文字」與「視覺」之間的底層壁壘。
###### 核心技術限制與痛點
- **影像模糊硬傷（Continuous Blur) - 傳統限制**：
    - **痛點**：由於傳統 VAE 強制將潛在空間收斂到連續的常態分佈，解碼器在生成時為了保險起見，會傾向取平均值，導致生出來的圖片細節模糊、像蒙了一層霧。
    - **PM 的產品解法**：如果產品追求高質量的視覺創意（如藝術畫作），**必須放棄單獨使用傳統 VAE**，應改用擴散模型（Diffusion）。
- **訓練天平極度脆弱（Posterior Collapse）**：
    - **痛點**：重建損失與 KL 散度的動態平衡非常難抓，RD 團隊在調整這個超參數時常需要耗費大量時間進行網格搜索，否則模型隨時會罷工（罷工時解碼器無論輸入什麼都只會吐出一團灰色的模糊殘影）。

#### 3. 擴散模型 (Diffusion Models)
##### 骨架架構與核心運作原理
###### 核心商業基石：「破壞與重建」的影像洗滌機制
- **生成邏輯**：不同於文字自迴歸模型的「接龍」，擴散模型生成影像的邏輯是 **「除噪（Denoising）」**。
- **訓練階段（無情破壞）**：拿一張乾淨的產品照片，分 1000 個步驟慢慢加入雜訊（噪點），直到照片徹底變成一團像電視機沒訊號時的「灰白雪花畫面（純雜訊）」。
- **生成階段（腦補重生）**：給 AI 一團隨機的純雜訊，讓 AI 發揮「除噪能力」，把雜訊一步步擦除。在擦除的過程中，結合使用者輸入的提示詞，最終「洗出」一張全新、高清的影像。
- **PM 白話理解**：這就像傳統照相館的「沖洗照片」。AI 的任務不是憑空畫圖，而是把一塊充滿雜訊的毛玻璃慢慢擦乾淨，直到看清後面的風景。
###### 傳統骨架：基於 U-Net (CNN) 的區域局部網路
- **代表模型**：Stable Diffusion v1.5 / v2.1 / SDXL、DALL-E 2、Google Imagen。
- **運作結構**：使用以 **CNN（卷積神經網路）** 為核心的 **U-Net 結構**。
- **結構特性**：
    - **見樹不見林**：U-Net 非常擅長處理影像的局部特徵（例如完美辨識哪裡是貓的毛髮、哪裡是花瓣的邊緣），所以畫面細節非常精緻。
    - **文字理解硬傷**：因為早期模型對長文字的理解能力有限（SD 1.5 的 U-Net 其實也含注意力層，但搭配的 CLIP 文字編碼器只能讀約 77 個 Token、對長句理解較弱），當提示詞很長或很複雜時（例如：「一個左手拿咖啡、右手拿報紙、戴著紅色帽子的工程師」），傳統骨架常常會把特徵移花接木，發生「左手咖啡不見了」或「帽子變成藍色」的**條件錯亂問題**。
###### 新版骨架：基於 DiT (Diffusion Transformer) 的全局自注意力網路
- **代表模型**：**Sora (OpenAI 影片生成)**、Flux.1、Stable Diffusion 3 (SD3 / SD3.5)。
- **運作結構**：將老舊的 U-Net 淘汰，改用與 ChatGPT 同款的 **Transformer** 作為計算骨架。
- **結構特性**：
    - **影像文字化（Patch 化）**：將影像切成一塊塊像素方塊（像文字的 Token 一樣），投餵給 Transformer 計算。
    - **過目不忘的大局觀**：利用全局自注意力機制，模型可以同時處理「整張畫面」與「長篇文字提示詞」之間的每一個對應關係。
    - **產品革命**：新骨架大幅改善了傳統骨架不聽話的問題，對**長提示詞的理解力精準度暴增**，這也是 Sora 等影片模型能理解長篇分鏡描述的關鍵之一。

##### 創造性（Creativity）與控制能力（Generation Control）
- 擴散模型在多媒體產品上的創造力極高，而 PM 必須知道產品線如何控制它的輸出。
###### (1) 創造性（多樣性）的來源
- 每次生成時，系統給模型的「初始純雜訊（隨機種子 Seed）」都是隨機的。因為起點的雪花圖案不同，AI 擦除雜訊的推進路徑就不同，這讓擴散模型能源源不絕地創造出成千上萬種完全不重複的創意畫作。
###### (2) 控制能力的兩大核心參數
- **CFG Scale (提示詞相關性 / 引導權重)**
    - **PM 白話理解**：**「AI 聽話程度的緊箍咒」**。
    - **低數值（如 4-6）**：給 AI 很大的自由度，畫面創意度高，但可能會稍微偏離提示詞。
    - **高數值（如 12-15）**：強迫 AI 必須死死盯著提示詞的每一個字，但調得太高會導致畫面色彩過度飽和、邊緣崩壞。
- **Inference Steps (推論去噪步數)**
    - **PM 白話理解**：**「擦拭毛玻璃的次數」**。
    - **低步數（如 15-20 步）**：擦得不夠乾淨，出圖速度極快（低延遲），但畫面可能會有殘留的模糊感。
    - **高步數（如 50-100 步）**：擦得極度精細，細節無可挑剔，但伺服器運算時間會拉長，大幅增加用戶等待的時間（高延遲）。

##### 提示工程（Prompt Engineering）與輸入優化深度
- **傳統骨架 (U-Net) 的優化**：提示詞必須非常「碎片化」、「公式化」（例如 RD 常用的：`masterpiece, best quality, 4k, cinematic lighting` 這種標籤堆疊），因為傳統骨架看不懂人類的複雜長句。
- **新版骨架 (DiT) 的優化**：可以直接輸入**自然語言長句（Natural Language Prompt）**。你可以像對導演講戲一樣，寫下一整段故事背景，新版 Transformer 骨架能完美消化並將其拆解映射到畫面各個角落。

##### 架構複雜度與硬體代價：多步驟去噪的 UX 挑戰
- **簡單任務（輕量級 / 加速模型）**：
    - **技術策略**：採用蒸餾技術（如 LCM, SDXL-Lightning）。
    - **產品優勢**：把原本需要 30 步的去噪過程縮短到「只需 1 到 4 步」，實現 **「即時生成（Real-time Generation）」**。可在單張消費級顯卡或筆電端運行，適合做即時濾鏡或快速靈感發想產品。
- **複雜應用需求（高效能影片/高解析度模型）**：
    - **技術策略**：採用高參數量的 DiT 架構（如 Sora、Flux.1-Pro）。
    - **硬體成本**：影片要逐格生成且維持前後一致，運算量遠高於單張圖片，需要資料中心級 GPU，雲端算力成本極其高昂。
    - **產品營運考量**：在規劃這類產品時，PM 必須設計嚴格的**算力點數限制（Token/Credit 消耗機制）**，否則用戶狂刷圖會直接把公司的伺服器預算燒光。

##### 訓練階段與超參數設置
- **損失函數（Loss Function - Noise Prediction）**：
    - **核心邏輯**：擴散模型的訓練分數非常簡單，就叫 **「噪聲預測誤差」** 。訓練時，模型去猜「這一步被加了多少隨機雜訊」，猜得越準，誤差（Loss）越低。
    - **PM 理解**：就像訓練一個鑑定師，只要他能精準認出畫面中哪些是「雜質」，他自然就知道怎麼把雜質完美的洗掉。
- **防過擬合機制與訓練量**：
    - 每次訓練都會隨機抽一個時間步與一組隨機雜訊，同一張圖每次看到的「考卷」都不同，具備天然的資料增強與防過擬合效果。
    - ⚠️ 但擴散模型**並非「少 Epochs」**：它通常需要長時間、多輪訓練才能收斂。在小資料集上訓練過度，還可能直接「背出」訓練圖片（記憶化問題，帶有版權與隱私風險）。

##### 適用場景與限制
###### 最佳適用場景
擴散模型在 **「創意視覺創作、高品質多媒體合成、圖像局部修改」** 上是絕對的產品首選：
- **AI 藝術與行銷設計產品**：Text-to-Image（文生圖）、Text-to-Video（文生影片）。
- **圖像局部重繪（Inpainting / Outpainting）**：
    - **場景**：電商產品換背景、AI 虛擬試穿、老照片邊緣無限延伸擴展。
    - **原因**：把要修改的地方塗黑變成雜訊，讓擴散模型重新除噪腦補，能與周圍原生畫面完美融合。
###### 核心技術限制與痛點
- **無法瞬間出圖（Inference Latency）**：
    - **痛點**：因為必須走完那 20~30 步的除噪流水線，不管算力再快，都一定存在物理上的等待時間，無法像傳統 GAN 網路那樣一次輸出整張圖（蒸餾模型可降到 1～4 步，但仍非一次完成）。
    - **PM 產品解法**：介面一定要設計**「進度條」或「去噪過程的即時毛玻璃預覽動畫」**，舒緩使用者等待的焦慮感。
- **文字渲染崩潰（Text Rendering Hardship）**：
    - **痛點**：擴散模型是在像素層面除噪，它其實不認識英文字母或中文。所以你在提示詞寫「招牌上要寫 APPLE」，它常常會畫出少一橫、多一豎的火星文。
    - **PM 技術解法**：若產品有嚴格的文字生成需求，必須要求 RD 引入最新結合 T5/CLIP 強大文字編碼器的 **DiT 新骨架（如 SD3.5 / Flux）**，才能大幅降低招牌文字破圖的機率。

#### 4. 生成對抗網路 (Generative Adversarial Networks, GANs)
##### 骨架架構與核心運作原理
###### 核心商業基石：「雙強相爭、相生相剋」的賽局機制
- **生成邏輯**：GAN 既不玩文字接龍（自迴歸），也不洗毛玻璃（擴散模型），它的核心是**兩個 AI 網路的博弈對抗**。
- **生成器 (Generator) → PM 白話叫「偽鈔製造集團」**：負責從隨機雜訊中畫出假照片，目標是做到天衣無縫，徹底騙過對手。
- **判別器 (Discriminator) → PM 白話叫「中央銀行鑑定專家」**：負責收下照片，鑑定這到底是「真實世界拍的」還是「生成器畫的贗品」，並給出真偽機率值。
- **演進過程**：雙方在訓練中互相反覆交手。生成器畫得越來越逼真，判別器眼光越來越毒辣，直到判別器完全分不出真假（勝率各佔 50%），模型就大功告成。
###### 傳統骨架：基於 CNN (卷積神經網路) 的結構
- **代表模型**：DCGAN、StyleGAN 家族 (v1 / v2 / v3)、CycleGAN（風格轉換）。
- **運作結構**：完全以 **CNN（卷積神經網路）** 為核心。生成器用轉置卷積（Deconvolution）把噪聲放大成影像，判別器用標準卷積逐步將影像縮小進行特徵分類。
- **結構特性**：
    - **細節魔王**：CNN 骨架極度擅長處理紋理、皮膚毛孔、髮絲等微觀局部特徵。這也是為什麼 StyleGAN 生成的虛擬人臉，連雀斑、眼球血絲都逼真到嚇人。
    - **大局觀缺失**：缺乏全局自注意力，有時候會出現「左眼瞳孔是圓的，右眼瞳孔卻變方或變形」的結構不連貫硬傷。
###### 新版骨架：基於 ViT (Vision Transformer) 的自注意力網路
- **代表模型**：TransGAN、ViTGAN、GigaGAN（CNN + 注意力混合）。（注意：StyleGAN-XL 仍是 CNN 骨架，不屬於 ViT 系。）
- **運作結構**：將傳統的 CNN 核心大換血，改用 **Vision Transformer (ViT)** 作為對抗的運算骨架。
- **結構特性**：
    - **大局觀互補**：引入全局自注意力機制，讓生成器在畫左眼的同時，能死死盯著右眼的形狀，明顯改善了傳統 CNN 骨架「兩眼不對稱、背景線條扭曲」的硬傷，使整張照片的全局空間結構更加穩固。

##### 創造性（Creativity）與控制能力（Generation Control）
- GAN 過去在控制力上非常吃技術，PM 必須了解它的潛在特徵控制邏輯。
###### (1) 創造性（多樣性）的來源
- 只要在推論時投餵一串不同的隨機數位（潛在向量 Latent Vector），生成器就能在彈指之間，將這串數位「腦補解碼」成一張世界上不存在的全新臉孔或全新物件。
###### (2) 控制能力的兩大核心機制
- **潛在空間特徵控制 (Latent Space Manipulation)**
    - **PM 白話理解**：**「操控特徵方向盤」**。
    - **表現**：類似 VAE，資深 RD 可以透過數學方法，在 GAN 的特徵基底中找到特定的「特徵向量」。只要在推論時往該方向微調數值，就可以在不破壞照片畫質的情況下，精準讓照片中的人「一秒變老」、「戴上眼鏡」或「把短髮變長髮」。
- **條件式生成 (Conditional GAN / cGAN)**
    - **PM 白話理解**：**「給 AI 下分類標籤」**。
    - **表現**：在輸入端直接強制綁定類別（例如指定「貓」或「狗」），限制生成器只能在指定的產品大類目下發揮創意。

##### 提示工程（Prompt Engineering）與輸入優化深度
- **傳統與新版 GAN 骨架的限制**：GAN **天生不適合做文字提示詞（Text Prompt）生成**。它不像擴散模型那樣能聽懂人類的一整段長難句。
- **輸入優化深度**：GAN 的輸入優化多屬於 **「影像對影像 (Image-to-Image)」**。例如在 CycleGAN 中，輸入是一張普通的風景照，提示與引導是透過另一個數據集（如梵谷的畫作群），強迫模型學習「把真實照片瞬間轉化為梵谷畫風」的特殊對照映射。

##### 架構複雜度與硬體代價：一眨眼就出圖的終極推論優勢
- **簡單生成任務（輕量級 / 邊緣端部署）**：
    - **技術策略**：壓縮後的 GAN 網路。
    - **產品優勢**：GAN 具有擴散模型望塵莫及的 **「秒出圖（One-shot Generation）」** 特性。它不需要像擴散模型那樣苦苦等待 30 步的除噪流水線，它只需做「一次」前向運算（Forward Pass），一眨眼就能噴出一張高清圖。硬體開銷極低，非常適合部署在手機 App 中做即時 AI 美顏特效、虛擬濾鏡。
- **複雜應用需求（高效能高動態生成）**：
    - **代表模型**：StyleGAN-XL。
    - **硬體成本**：訓練階段是著名的「算力碎紙機」，需要大量頂級 GPU 進行極其不穩定的漫長訓練。但**只要模型訓練好落地後，推論階段（用戶使用時）非常省算力**，伺服器反應極快，運營成本相較擴散模型低很多。

##### 訓練階段與超參數設置
- **損失函數（Loss Function - Minimax Loss）**：
    - **核心邏輯**：大名鼎鼎的 **「極小化極大賽局損失 (Minimax Loss)」**。
    - **PM 理解**：這是一場零和賽局。生成器的分數取決於「判別器看走眼的機率」；判別器的分數取決於「抓到偽鈔的精準度」。一方的得分就是另一方的失分，逼著雙方在內捲中雙雙變強。（實務上為了訓練穩定，生成器多改用 non-saturating loss，並非嚴格零和。）
- **過擬合防範與訓練崩潰硬傷**：
    - **致命硬傷：模式崩潰 (Mode Collapse)**：這是 GAN 訓練最常發生的災難。生成器突然發現某一種假照片（例如某一隻特定角度的貓）特別容易騙過判別器，它就會**從此開始擺爛，不管用戶輸入什麼，都只重複畫那一張一模一樣的照片**。
    - **PM 的專案時程預防針**：防範此問題依賴極其脆弱的超參數微調（如加入梯度懲罰 WGAN-GP）。RD 團隊在訓練 GAN 時，開發時程（R&D Timeline）往往高度不可控，因為模型隨時可能在最後一秒無預警崩潰走火入魔，需要 PM 在專案時程上預留彈性。

##### 適用場景與限制
###### 最佳適用場景
GAN 在 **「極致低延遲、即時風格變換、局部超解析度修復」** 的產品任務上是絕對的霸主：
- **即時互動式 AI 產品**：手機美顏相機（變老變年輕濾鏡）、AI 虛擬試妝、直播即時換臉（Deepfake 類應用）。
- **影像超解析度修復 (SRGAN)**：
    - **場景**：將 480P 的老舊經典電影、監視器畫面，快速放大修復成高解析度畫質。
    - **原因**：生成速度極快，能滿足影音串流平台即時觀看、不卡頓的 UX 要求。
###### 核心技術限制與痛點（PM 的產品風險控管）
- **訓練極度不穩定（Training Instability）**：
    - **痛點**：GAN 的雙網路對抗就像走鋼索，只要其中一方太強（例如判別器太嚴格，生成器不管怎麼畫都被打零分），生成器就會直接放棄學習，導致產品研發陷入死胡同。
- **缺乏天馬行空的全新創造力**：
    - **痛點**：GAN 只能在看過的數據範圍內做精細的特徵揉合。如果你要求它憑空創造一個「騎著摩托車在火星上的北極熊」，它的結構與畫面完整度會被擴散模型（Diffusion）全面輾壓。

#### 5. 基於能量的模型與流程模型 (Energy-Based & Flow-Based Models)
##### 骨架架構與核心運作原理
###### 核心商業基石：「物理世界的精確映射與防呆機制」
- **生成邏輯**：這兩類模型不玩貓捉老鼠（GAN），也不猜雪花噪點（擴散模型），它們是生成式 AI 界極致的**「硬核數學派」**。它們的核心任務是**直接建模數據的「機率分佈密度」**（Flow 可精確計算；EBM 因配分函數難算，只能近似）。
- **基於能量的模型 (EBM) → PM 白話叫「重力尋寶偵測器」**：
    - 模型把真實世界的數據定義為「能量最低、最穩定的狀態」（就像水往低處流，山谷底部的能量最低）。
    - AI 的任務是建立一個能量函數，只要輸入的資料越真實、越合理，能量就越低（得分越高）；如果輸入荒謬不合理的資料（例如畫出一隻有八隻腳的貓），能量就會飆高。
- **流程模型 (Normalizing Flows) → PM 白話叫「百分之百可逆的百變黏土」**：
    - 模型透過一系列「可逆（Reversible）」的數學魔術變換，將一團非常簡單、完美的圓形常態分佈（就像標準的黏土原料），一步步捏成極度複雜的真實數據分佈（如人臉或複雜語音）。
    - 因為每一步數學變換都必須是「可逆的」，所以你怎麼捏出來，就能怎麼百分之百完美地還原回去。
###### 傳統骨架：基於標準卷積與可逆密度計算的網路
- **代表模型**：RealNVP、Glow（能瞬間調整人臉特徵的流程模型）；EBM 代表：JEM（Joint Energy-based Model）。
- **運作結構**：傳統上使用特殊的 **CNN（卷積神經網路）** 變體構成。為了確保數學上的「可逆性」，網路的內部結構受到極其嚴格的限制（例如使用耦合層 Coupling Layer，讓雅可比矩陣成為三角矩陣，行列式才算得動）。
- **結構特性**：
    - **精準計算**：能精確計算數據的似然值（機率密度），不像 VAE 只算下界。
    - **結構死板**：因為數學限制太多，傳統 CNN 骨架在設計時就像帶著腳鐐跳舞，每一層都必須可逆、輸入輸出維度必須相同，架構設計自由度低、參數效率差。
###### 新版骨架：基於 Transformer 的連續流動網路
- **代表模型**：Flow-Matching、Continuous Normalizing Flows (CNF) 結合 Transformer。
- **運作結構**：淘汰死板的傳統限制，改用 **Transformer（自注意力機制）** 來模擬數據的連續流動與能量變化。
- **結構特性**：
    - **算力大解放**：新骨架利用 Transformer 強大的矩陣吞吐量，把可逆的數學變換變成像流水一樣的「連續向量場（Vector Fields）」。這讓它擺脫「每層都要可逆」的架構限制，能吃滿 GPU 算力，具備生成高品質大圖與複雜音訊的能力。
    - **與擴散模型是近親**：Flow Matching 同樣是「從雜訊一步步走到資料」，差別在於學一條**更直的路徑**，所以能用更少步數出圖。Stable Diffusion 3、Flux 的核心訓練方法就是它（Rectified Flow）。

##### 創造性（Creativity）與控制能力（Generation Control）
- 這類模型走的是「嚴謹科學風」，其控制能力是所有模型中最具備數學保證的。
###### (1) 創造性（多樣性）的來源
- 流程模型（Flow）的創造性來自於底層那顆絕對完美的「標準常態分佈種子」。因為基底的數學空間非常平滑、沒有任何斷層，抽樣過程穩定，不會出現 GAN 的「模式崩潰」（只生成同一種樣本）。⚠️ 但可逆性保證的是「機率算得準」，**不保證生成品質**：傳統 Flow（如 Glow）的畫質其實不如 GAN 與擴散模型，仍可能生成不自然的樣本。
###### (2) 控制能力的絕對精準性
- **精確的似然估計 (Exact Likelihood Computation)**
    - **PM 白話理解**：**「自帶完美的真偽對齊儀器」**。
    - **表現**：模型能精確算出「這筆數據在模型眼中有多常見」（似然值）。例如用正常醫療影像訓練後，新影像的似然值異常低，就代表可能是異常樣本。⚠️ 兩點注意：(1) 似然值是「機率密度」，不是「99% 是正常」這種分類機率；(2) **自迴歸模型（GPT）也能精確計算似然**（鏈式法則逐項相乘）。無法精確計算的是 GAN（沒有似然）、VAE 與擴散（只能算下界 ELBO）、EBM（只能近似）。

##### 提示工程（Prompt Engineering）與輸入優化深度
- **文字提示詞的限制**：這兩類模型**天生不認識人類的感性文字提示詞**。你對它寫 `masterpiece` 或浪漫的形容詞，它完全無法直接消化。
- **輸入優化深度**：它們的輸入優化屬於**「物理特徵與邊界條件的精準輸入」**。例如在科學計算中，輸入的是分子座標、能量函數等物理條件，模型學習這些物理量的機率分佈並抽樣。（註：氣象生成模型如 Google GenCast 實際上用的是擴散模型。）

##### 架構複雜度與硬體代價：超巨大的參數體積與推論拉鋸
- **簡單生成任務（輕量級模擬）**：
    - 由於數學架構非常嚴謹，輕量級的流程模型非常少見，通常只能處理低維度的簡單訊號、基本的音訊特徵壓縮。
- **複雜應用需求（高效能科學模擬器）**：
    - **硬體成本**：新版 Flow Matching（Flux、Stable Diffusion 3 的核心訓練方法）搭配大型 Transformer 後，參數動輒數十億（Flux.1 約 120 億），需要資料中心級 GPU。但成本主要來自「模型規模」，不是 Flow 本身；Flow Matching 讓生成路徑更直，反而**能用更少步數出圖**，推論效率通常優於傳統擴散。

##### 訓練階段與超參數設置
- **損失函數（Loss Function - Negative Log-Likelihood）**：
    - **核心邏輯**：**「負對數似然損失 (NLL Loss)」**。
    - **PM 理解**：評分標準極其單純——「真實數據在模型裡出現的機率越高，NLL Loss 就越低」。目標是把模型內部的數學天平，調整到與真實物理世界完全一模一樣。
- **無崩潰風險的超強訓練穩定度**：
    - **技術優勢**：這類模型在訓練時**完全沒有 GAN 的「模式崩潰（Mode Collapse）」風險**，也避開了 VAE 的「潛在空間崩潰」。只要給它足夠的時間和算力，它的訓練曲線會非常平穩地上升，開發時程（R&D Timeline）相較於 GAN 極度好預測，RD 團隊不需要天天燒香拜佛擔心模型走火入魔。（⚠️ 此優點主要指 Flow；EBM 訓練需要 MCMC 抽樣，其實相當不穩定。）

##### 適用場景與限制
###### 最佳適用場景
這兩類模型在 **「科學物理模擬、極致高擬真音訊生成、高安全防偽異常檢測」** 的產品任務上擁有無可取代的地位：
- **AI 科學與氣象、藥物模擬產品**：
    - **場景**：分子構型取樣（如 Boltzmann Generators）、物理模擬、需量化不確定性的科學應用。
    - **原因**：科學應用需要可靠的機率估計，能說清楚「這個結果有多可能」，而不只是生成看起來像的樣本。
- **高階音訊合成 (Audio Synthesis)**：
    - **代表模型**：WaveGlow（NVIDIA）。
    - **場景**：即時、高品質的 AI 語音客服，高度還原真人的呼吸聲與特殊音頻特徵。
    - **原因**：利用流程模型可逆、可精確計算機率的特點，能精確建模對細節要求極高的連續音訊波形。
###### 核心技術限制與痛點
- **架構設計的數學門檻極高**：
    - **痛點**：這類模型是純粹的數學怪獸。團隊裡如果沒有專精於機率幾何、拓撲學的頂尖演算法博士（Algorithm PhD），光是設計那個「可逆架構」就會讓普通的 RD 團隊進度卡死。
- **商業化落地的性價比低（ROI 較差）**：
    - **痛點**：傳統 Flow（Glow、RealNVP）為了可逆性犧牲了參數效率，畫質不如擴散模型；EBM 抽樣慢、訓練難。在商業視覺市場屬於**「叫好不叫座、藏在後台的硬核科學功臣」**。
    - ⚠️ **例外：Flow Matching** 已經翻身成為主流，Stable Diffusion 3、Flux 等頂級文生圖模型都以它為核心。

#### 五大主流趨勢

| 趨勢 | 白話 | 代表 |

| **推理模型**（Reasoning Models） | 回答前先「想一想」，用更多推論時間換正確率 | OpenAI o 系列、DeepSeek-R1、Claude 的延伸思考 |
| **影像生成：DiT＋Flow Matching** | 擴散模型骨架換成 Transformer，訓練方法改用路徑更直的 Flow Matching，出圖更快更好 | Stable Diffusion 3、Flux、Sora 類影片模型 |
| **自迴歸也能畫圖** | 部分新模型把圖片當成 Token，用「接龍」方式生成圖片，文字渲染更準 | GPT-4o 影像生成等 |

#### 長上下文 vs RAG

- 新模型的上下文視窗已達數十萬到百萬 Token，可以一次讀完整份文件。
- 但 **RAG 仍是主流**：文件量遠超上下文時、需要即時更新知識時、要控制成本時，RAG 都比較划算。
- 實務常見：**RAG 先找出相關段落 → 再用長上下文模型完整閱讀**。

#### 從「生成內容」到「執行任務」：AI Agent

- **Agent（智慧代理）**：模型不只回答，還能**呼叫工具**（查資料庫、寄信、下單）並多步驟完成任務。
- 關鍵技術：**Function Calling（函式呼叫）**、**MCP（Model Context Protocol，模型與工具之間的標準介接協定）**。
- PM 觀點：Agent 能做的事變多，**風險也跟著變大**（可能執行錯誤操作），需要權限控管與人工確認關卡。

#### 值得關注的新架構

- **狀態空間模型（SSM，如 Mamba）**及**Transformer 混合架構**：處理超長序列時更省記憶體，部分新模型已採用，但尚未取代 Transformer。

### 三、實務選型

#### 實務選型的第一個問題：不是選「演算法」，是選「基礎模型」

教材從五大演算法家族談選型，但企業實務上**幾乎不會自己從頭建模型**。真正的選型順序是：

| 決策 | 選項 | 考量 |
|---|---|---|
| ① 閉源 API 還是開源權重？ | **閉源**：GPT、Claude、Gemini<br>**開源權重**：Llama、Qwen、Gemma、Mistral、DeepSeek | 資料隱私（能否地端部署）、成本、效能、授權條款 |
| ② 模型多大？ | 大模型 vs 小模型（SLM） | 任務難度、延遲、成本、是否要在手機或筆電上跑 |
| ③ 怎麼客製？ | Prompt → RAG → 微調 | 見 [[訓練模型與如何優化]] 的成本階梯 |
| ④ 需不需要推理模型？ | 一般模型 vs 推理模型 | 複雜推理才需要，但較慢、較貴 |

#### 更新版選型速查（實務版）

| 需求 | 2026 年主流選擇 |
|---|---|
| 一般文字問答、客服、摘要 | 閉源或開源 LLM API＋RAG |
| 資料不能出公司 | 開源權重模型，地端或私有雲部署 |
| 複雜分析、數學、程式 | 推理模型 |
| 手機上即時執行 | 小型模型（SLM）＋量化 |
| 高品質圖片／影片 | DiT＋Flow Matching 類模型 |
| 圖文混合理解 | 原生多模態模型 |
| 自動執行多步驟任務 | Agent 架構＋工具呼叫 |
