#### 缺失值補值怎麼選
| 資料狀況 | 補值方式 |
|---|---|
| 大致對稱、沒有極端值 | 平均數 |
| **偏態、有極端值** | **中位數** |
| 類別資料 | 眾數 |
| **時間序列** | **前向填補（ffill）或插值** |
| 缺失本身可能有意義 | 補值＋加一個「**是否缺失**」的指標欄位 |

> [!warning] 陷阱題
> 1. `df.isnull()` 和 `df.isna()` **完全相同**（互為別名）；`isNaN()`、`isnan()` 在 pandas **不存在**。
> 2. Python 函式的**預設參數如果是 list 或 dict，會在多次呼叫之間共用**，這是經典 bug。
> 3. 平均數 > 中位數很多 → 右偏 → 補值用**中位數**。
> 4. 同一位病患（或同一個用戶）的資料**不能同時出現在訓練集與測試集**，要依「人」分組切分。

#### 115-1 Q41｜右偏收入欄位的補值
（情境：共享乘車平台的司機每日營運資料 driver_daily_stats.csv，欄位有 driver_id、daily_earnings、region、app_version、gps_ping_rate。）
分析師執行：

```python
import pandas as pd
df = pd.read_csv('driver_daily_stats.csv')
print(df['daily_earnings'].describe()[['mean', '50%', 'max']])
```

輸出：mean 223.41、50% 128.55、max 4500.00。若 daily_earnings 約有 5% 遺失值，且規劃以線性迴歸預測未來收入，為盡可能保留原有分布並降低補值偏差，哪一種處理最合理？
- (A) `df['daily_earnings'].fillna(df['daily_earnings'].mean(), inplace=True)`
- (B) `df['daily_earnings'].fillna(df['daily_earnings'].median(), inplace=True)`
- (C) `df['daily_earnings'].fillna(df['daily_earnings'].max(), inplace=True)`
- (D) 直接刪除所有遺失資料，因數值型欄位不適合補值

> [!success]- 點開看答案
> **答案：B**
>
> 從輸出判讀：平均 223 遠大於中位數 128，最大值高達 4500 → **嚴重右偏**，平均數被少數高收入司機拉高了。用平均數補值會讓補進去的值偏高，中位數比較能代表「一般司機」。
> (D) 錯在「數值型欄位不適合補值」這個說法本身就不對。
>
> ⚠️ **程式寫法補充**：`df['col'].fillna(..., inplace=True)` 在 **pandas 2.x 會出現 ChainedAssignment 警告**，未來版本可能不再生效。建議寫法是 `df['daily_earnings'] = df['daily_earnings'].fillna(df['daily_earnings'].median())`。

#### 114-2 Q49｜計算各欄位遺漏值個數
對 marketing.csv 計算各變數遺漏值個數，得到：youtube 0、facebook 1、newspaper 0、sales 0。下列哪些寫法可以得到此結果？
- 選項 A：`df.isnull().sum()`
- 選項 B：`df.isNaN().sum()`
- 選項 C：`df.isna().sum()`
- 選項 D：`df.isnan().sum()`

(A) 選項 D　(B) 選項 B、C、D　(C) 選項 A、C　(D) 選項 A、B、C

> [!success]- 點開看答案
> **答案：C**
>
> pandas 的 `isna()` 和 `isnull()` 是**同一個函式的兩個名字**。B 和 D 是混淆用的假函式：
> - `isNaN` 是 **JavaScript** 的函式名稱。
> - `isnan` 是 **NumPy**（`np.isnan()`），不是 DataFrame 的方法。
>
> `.isna()` 產生 True／False 表格，`.sum()` 把每欄的 True 當作 1 加總，就得到每欄的缺失數。

#### 115-1 Q39｜可變預設參數的陷阱
自動化資料清洗管線中，用來補齊缺失欄位的 Python 函式如下。連續處理兩筆資料後，row2['tags'] 的內容為何？

```python
def process_record(record, tags=[]):
    tags.append("checked")
    record['tags'] = tags
    return record

row1 = process_record({"id": 1})
row2 = process_record({"id": 2})
```

- (A) `["checked", "tags"]`
- (B) `[]`
- (C) `["checked", "checked"]`
- (D) 拋出 KeyError 錯誤，因為字典中沒有 tags 鍵值

> [!success]- 點開看答案
> **答案：C**
>
> 一步一步追：
> 1. Python 在**定義函式時**就建立了**一個** `[]` 當預設值，之後每次呼叫都用**同一個** list。
> 2. 處理 row1：這個 list 變成 `["checked"]`。
> 3. 處理 row2：還是同一個 list，再 append 一次 → `["checked", "checked"]`。
> 4. 而且 row1['tags'] 和 row2['tags'] 指向同一個物件，所以**兩筆最後都是** `["checked", "checked"]`。
>
> (D) 錯在 `record['tags'] = ...` 是**新增**鍵值，不會 KeyError。
>
> **正確寫法**（業界標準）：
> ```python
> def process_record(record, tags=None):
>     if tags is None:
>         tags = []
>     tags.append("checked")
>     record['tags'] = tags
>     return record
> ```

#### 115-1 Q17｜ICU 敗血症預測的資料處理
ICU 敗血症預測：120 位病患的生命徵象每 5 分鐘一筆，敗血症樣本僅 3.2%。資料問題：血氧有 10～30 分鐘連續缺失、部分血壓感測器隨時間系統性偏高（感測器漂移）、敗血症標註時間有約 ±2 小時誤差、不同病患的正常基準差異很大。下列何種處理與建模方式最適當？
- (A) 缺失值以整體平均填補，不處理感測器漂移，標註區間由 6 小時擴大至 8 小時，以 ROC-AUC 為主要指標
- (B) 缺失值線性插值，連續缺失過長則刪除，以 Z-score 標準化處理感測器漂移，交叉驗證採隨機切分，未避免同一病患同時出現在訓練與測試集
- (C) 刪除所有含缺失值的資料，Min-Max 正規化，不考慮病患差異，以 Accuracy 評估，採分層 K-Fold
- (D) 缺失值前向填補並加入缺失指標特徵，以感測器 72 小時滾動中位數校正漂移，處理標註雜訊，以個別病患基準建模，交叉驗證採病患分組，評估採 PR-AUC 與 Recall

> [!success]- 點開看答案
> **答案：D**
>
> 這題要把四個問題逐一配對解法，只有 D 全部處理到：
> | 問題 | D 的做法 |
> |---|---|
> | 連續缺失 | 前向填補＋**缺失指標**（缺失本身可能代表病況） |
> | 感測器漂移 | **滾動中位數**校正（Z-score 只是換單位，校正不了漂移） |
> | 病患基準不同 | **個別病患基準**（例如相對自己平常值的變化量） |
> | 資料洩漏 | **病患分組**交叉驗證（GroupKFold） |
> | 3.2% 不平衡 | **PR-AUC＋Recall**，不用 Accuracy |
>
> (B) 最致命的錯誤是「同一病患同時出現在訓練與測試集」，模型會記住病人本身的特徵，測試分數虛高。

#### 114-2 Q11｜即時監控大量 IoT 裝置
公司需即時監控大量物聯網裝置的異常行為，哪一種組合最適合？
- (A) 傳統關聯式資料庫＋圖形視覺化
- (B) 批次資料處理＋雲端備份
- (C) 大數據平台＋即時資料分析技術
- (D) Word 文件＋手動標註

> [!success]- 點開看答案
> **答案：C**
>
> 「**大量**」→ 大數據平台；「**即時**」→ 串流分析。(B) 批次處理做不到即時。
> 常見技術組合：**Kafka**（收資料）＋ **Flink／Spark Streaming**（即時運算）。
