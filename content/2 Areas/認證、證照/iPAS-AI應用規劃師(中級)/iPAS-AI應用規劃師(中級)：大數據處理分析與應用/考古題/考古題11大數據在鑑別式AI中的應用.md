#### 不平衡資料的標準解法
| 層面 | 做法 |
|---|---|
| 評估指標 | 不看 Accuracy，改看 **Recall、Precision、F1、PR-AUC** |
| 損失函數 | **Class Weight**、Cost-sensitive Learning、Focal Loss |
| 資料 | SMOTE、欠採樣（**只對訓練集**） |
| 決策 | **調整決策閾值** |

#### 閾值怎麼調
- **不能漏抓**（詐欺、外掛、癌症篩檢）→ 追求 **Recall** → **降低**閾值
- **不能誤判**（凍結帳號、垃圾信誤刪）→ 追求 **Precision** → **提高**閾值

> [!warning] 陷阱題
> 1. 99.5% 正常的資料，**永遠猜「正常」就有 99.5% Accuracy**，但一個詐欺都抓不到。
> 2. **ROC 曲線一定是單調遞增的**（閾值降低時，TPR 和 FPR 只會增加或不變）。
> 3. scikit-learn 的混淆矩陣：**列（row）是真實值、欄（column）是預測值**。
> 4. `average="weighted"` 是**依各類樣本數加權**的平均，不是簡單平均（那是 `macro`）。

## Notes
### 一、不平衡資料：不能只看 Accuracy
#### 115-1 Q20｜只用 Accuracy 選模型的問題
反詐欺模型在正常交易 99.5%、詐欺 0.5% 的資料上訓練。若只用整體 Accuracy 作為模型選擇的唯一指標，最可能產生什麼嚴重問題？
- (A) 模型訓練時間會大幅增加
- (B) 一個永遠預測為正常交易的模型即可達到 99.5% 準確率，但對詐欺交易的召回率為 0%，使準確率失去判別能力
- (C) 類別不平衡會導致梯度爆炸
- (D) 類別不平衡會直接導致過擬合

> [!success]- 點開看答案
> **答案：B**
>
> 這是不平衡資料的**第一定律**，背起來：永遠猜多數類就能拿到「多數類比例」的 Accuracy。

#### 115-1 Q25｜99.6% 準確率卻抓不到詐欺
信用卡詐欺僅佔 0.3%，模型測試 Accuracy 99.6%，上線後卻幾乎攔不到詐欺，還大量誤判正常交易。模型以 Accuracy 作為主要優化與評估指標。最適當的改善方向為何？
- (A) 持續優化 Accuracy
- (B) 改用 Precision 作為主要評估指標以降低誤報
- (C) 引入 Class Weight 或 Cost-sensitive Learning 調整損失函數
- (D) 移除少數類資料以提升穩定性

> [!success]- 點開看答案
> **答案：C**
>
> 問題的根源是模型在**訓練時**就不重視少數類（猜錯一筆詐欺和猜錯一筆正常，懲罰一樣）。**Class Weight** 讓猜錯詐欺的懲罰變大（例如 300 倍），模型就會認真學詐欺的樣子。
> (B) 只換「評估」指標，沒改「訓練」方式，模型本身不會變好；而且詐欺場景最重要的是**抓得到（Recall）**。
>
> ```python
> LogisticRegression(class_weight='balanced')       # sklearn
> XGBClassifier(scale_pos_weight=332)               # 約等於 正常數 ÷ 詐欺數
> ```

#### 115-1 Q43｜外掛偵測報告的質疑（選不是合理理由）
（情境：共享乘車平台，僅約 0.05% 的司機會用外掛竄改 gps_ping_rate 騙取補貼。）
新進資料科學家訓練二元分類模型，報告寫「整體 Accuracy 高達 99.95%，可直接上線」，並附上以下結果：

```
              precision    recall  f1-score
           0       1.00      1.00      1.00
           1       1.00      1.00      1.00
    accuracy                           1.00
   macro avg       1.00      1.00      1.00
weighted avg       1.00      1.00      1.00
```

資深工程師認為仍不足以支持直接上線。下列何者**不是**合理的質疑理由？
- (A) 在極度不平衡資料中，即使模型永遠預測正常，Accuracy 仍可能高達 99.95%
- (B) 報告中未呈現召回率，因此模型可能無法有效辨識真正的外掛司機
- (C) 異常偵測問題不可使用分類模型處理，僅能使用分群或離群值方法
- (D) 對於少數類比例極低的問題，若僅觀察 Accuracy，可能忽略對異常樣本的實際偵測能力

> [!success]- 點開看答案
> **答案：C**
>
> 「**不可**」「**僅能**」是絕對化說法。只要有標註資料，異常偵測**完全可以**用監督式分類模型處理（信用卡詐欺偵測就是最常見的例子）；分群、離群值方法是**沒有標註**時的選擇。
>
> 💡 **資深工程師真正該問的**：報告裡**全部都是 1.00**，在 0.05% 的極端不平衡下幾乎不可能，第一個要懷疑的是**資料洩漏**（例如某個特徵直接透露了答案），或測試集根本沒有外掛樣本。

#### 115-1 Q44｜「不能放過任何外掛」的閾值策略
營運長的決策目標：「對作弊零容忍。即使誤凍結部分正常帳號，後續可交由人工覆核；但不能放過任何一個真正的外掛司機。」調整決策機率門檻（預設 0.5）時，最合理的策略為何？
- (A) 選擇使作弊者 Recall 最大化的門檻，通常代表應降低 Threshold
- (B) 選擇使 Precision 最大化的門檻，通常代表應提高 Threshold
- (C) 固定使用 0.5，因為調整門檻會破壞訓練平衡
- (D) 選擇使特異度達到 100% 的門檻，確保正常司機不會被誤判

> [!success]- 點開看答案
> **答案：A**
>
> 「**不能放過任何一個**」＝不能有偽陰性＝最大化 **Recall**。把門檻從 0.5 降到例如 0.1，只要有 10% 可疑就先凍結，抓得更多、也誤判更多，誤判的交給人工覆核處理。
> (D) 剛好相反，那是「絕不誤判正常人」的策略。
>
> 📌 **PM 觀點**：這題示範了「**業務目標決定技術指標**」。決定閾值時要先問清楚：漏抓一個的成本 vs 誤判一個的成本，哪個比較貴？

### 二、ROC 曲線與分類報告
#### 115-1 Q23｜哪一條最不可能是 ROC 曲線
ROC 曲線由單一分類模型在不同決策閾值下形成，縱軸 TPR、橫軸 FPR。圖中有四條線：
- A：從左上角 (0, 1) 水平延伸到 (1, 1)
- B：在對角線上方、平滑往上凸起到 (1, 1) 的曲線
- C：先上升到一個高點後往下降，再往上升到 (1, 1) 的波浪形曲線
- D：從 (0, 0) 到 (1, 1) 的對角斜直線

何者最不可能是 ROC 曲線？
- (A) 水平線 A
- (B) 曲線 B
- (C) 曲線 C
- (D) 斜直線 D

> [!success]- 點開看答案
> **答案：C**
>
> 閾值從高往低調時，被判為陽性的樣本**只會越來越多**，所以 TPR 和 FPR 都**只增不減**，ROC 曲線一定是**單調遞增**的。曲線 C 中間往下掉，代表 TPR 減少，不可能發生。
> - A：完美分類器（AUC = 1）
> - B：一般的好模型
> - D：隨機猜測（AUC = 0.5）

#### 115-1 Q50｜混淆矩陣與加權 F1
（情境：鳶尾花資料集三分類邏輯迴歸。）

```python
>>> y_pred = log_reg.predict(X_test)
>>> cm = confusion_matrix(y_test, y_pred)
>>> f1 = f1_score(y_test, y_pred, average="weighted")
>>> print(cm)
[[13  0  0]
 [ 0  6  0]
 [ 0  1 10]]
>>> print("F1-score (Weighted):", f1)
F1-score (Weighted): 0.9671550671550672
Classification Report:
              precision    recall  f1-score   support
      setosa       1.00      1.00      1.00        13
  versicolor       0.86      1.00      0.92         6
   virginica       1.00      0.91      0.95        11
    accuracy                           0.97        30
   macro avg       0.95      0.97      0.96        30
weighted avg       0.97      0.97      0.97        30
```

下列描述何者正確？
- (A) cm 表示混淆矩陣，橫列表測試集的預測值
- (B) 混淆矩陣對角線數值皆大於非對角線數值表示模型過度擬合
- (C) f1_score 參數 average="weighted" 表示計算平均 f1_score
- (D) f1_score 計算時採用各類別 Precision 與 Recall 的調和平均，並加權考量類別不平衡性

> [!success]- 點開看答案
> **答案：D**
>
> - (A) ✗：sklearn 的混淆矩陣**橫列是真實值**、直欄是預測值。看第 3 列 `[0 1 10]`：真實為 virginica 的 11 筆中，有 1 筆被誤判成 versicolor。
> - (B) ✗：對角線大＝預測準。過擬合要比較**訓練 vs 測試**的表現，只看測試集的混淆矩陣無法判斷。
> - (C) ✗：太籠統。`macro` 是**簡單平均**（0.96），`weighted` 是**依樣本數加權**（0.97）。
> - (D) ✓：每類先算 F1（Precision 與 Recall 的調和平均），再依 support 加權。
>
> 驗算 weighted F1：(1.00×13 + 0.92×6 + 0.95×11) ÷ 30 ≈ 0.967 ✓

### 三、選對分類模型
#### 115-1 Q34｜要輸出可解釋機率的二元分類
依商品的價格區間、品牌、顏色、材質，將商品分類為高銷量（1）或低銷量（0），並希望模型輸出**可解釋的機率**（如 P = 0.73 表示 73% 機率為高銷量）。最適合的方法為何？
- (A) K-means 分群
- (B) 決策樹迴歸
- (C) 邏輯迴歸
- (D) 線性迴歸

> [!success]- 點開看答案
> **答案：C**
>
> 邏輯迴歸透過 Sigmoid 把輸出壓到 0～1，**直接就是機率**，係數也能解釋（例如「品牌 X 讓高銷量的勝算增加 2 倍」）。
> - (A) 分群是非監督式，沒有標籤。
> - (B)(D) 是**迴歸**模型，線性迴歸的輸出可能小於 0 或大於 1，不能當機率。

#### 115-1 Q33｜8 類書籍主題推薦的模型選型
依年齡、性別、過去購書類別偏好評分，預測讀者下次最可能購買的書籍主題（8 類）。資料已完整標註、達數十萬筆。除了準確率，也需考量訓練效率、可擴充性、快速訓練與線上部署。最適合哪種方法？
- (A) 多類別邏輯迴歸（Multinomial Logistic Regression）
- (B) SVM 搭配 One-vs-One
- (C) K-means 分群後將群集標籤作為分類結果
- (D) PCA 後以最大主成分作為分類依據

> [!success]- 點開看答案
> **答案：A**
>
> 多類別邏輯迴歸**訓練快、推論快、容易部署**，而且直接輸出 8 類各自的機率。
> (B) 的問題：**One-vs-One** 要訓練 C(8,2) = **28 個**分類器；而且 SVM（非線性核）的訓練時間大約隨資料量的平方到三次方成長，數十萬筆會很慢。
> (C)(D) 都是非監督方法，浪費了已標註的資料。

#### 115-1 Q40｜這段虛擬碼是哪種分類演算法
```
Input：train_data（每筆包含特徵和標籤）、test_point、X（要考慮的最近鄰個數）
Output：預測的分類標籤
Algorithm：
1. 初始化空列表 distances
2. 對每個訓練樣本 sample：計算與 test_point 的距離，把 (distance, 標籤) 加入 distances
3. 依距離升序排序
4. 取前 X 個距離最小的項目，記錄它們的標籤
5. 統計這 X 個標籤中出現次數最多的標籤
6. 回傳該標籤作為預測結果
```
- (A) K-近鄰（KNN）
- (B) K-means 分群
- (C) 支援向量機（SVM）
- (D) 隨機森林分類器

> [!success]- 點開看答案
> **答案：A**
>
> 「找最近的 X 個鄰居 → **多數決**」＝ KNN。
> ⚠️ 和 K-means 的差別：KNN 是**監督式分類**（有標籤、要預測新資料）；K-means 是**非監督式分群**（沒有標籤、要找群中心）。兩個名字都有 K，是最常見的混淆點，對照 [[考古題08常見的大數據分析方法]] 的 K-means 虛擬碼題。
> 補充：KNN **沒有訓練階段**（懶惰學習），每次預測都要跟所有訓練資料算距離，資料一大就很慢。

#### 114-2 Q10｜最適合用異常偵測的情境
下列哪一種情境最適合應用異常偵測（Anomaly Detection）技術？
- (A) 根據歷史銷售預測旺季是否會缺貨
- (B) 以信用風險模型預測顧客是否違約
- (C) 即時分析金融交易流，偵測與平常交易行為明顯不同的可疑交易
- (D) 監控登入次數，預測次日登入量變化

> [!success]- 點開看答案
> **答案：C**
>
> 關鍵字「**與平常明顯不同**」＝異常偵測。
> (A)(D) 是**預測**（迴歸、時間序列），(B) 是**分類**（有明確的違約標籤）。
