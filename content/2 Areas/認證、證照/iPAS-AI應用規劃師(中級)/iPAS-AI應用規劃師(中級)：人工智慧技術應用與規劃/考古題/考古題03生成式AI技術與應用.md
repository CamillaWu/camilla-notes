> **L21103 生成式 AI｜13 題**（114-2：8 題、115-1：5 題）。
> **出題方向明顯轉移**：114-2 還在考 GAN、VAE、Stable Diffusion 這類「生成模型原理」；115-1 改考 **LoRA、Prompt Tuning、災難性遺忘、Multi-Agent、ReAct**，也就是「**企業怎麼客製化 LLM、怎麼做 Agent**」。下一梯次很可能延續這個方向。

#### 三種 LLM 客製化方式
| 方式 | 改了什麼 | 成本 | 會不會忘記舊知識 |
|---|---|---|---|
| 全量微調（Full Fine-Tuning） | **所有**權重 | 最高 | 容易（災難性遺忘） |
| LoRA | 原權重**凍結**，只訓練旁邊加的**低秩小矩陣** | 低 | 較不會 |
| Prompt Tuning | 模型完全不動，只學輸入端的**軟提示向量** | 最低 | 不會 |

> [!warning] 陷阱題
> 1. **LoRA ≠ 知識蒸餾 ≠ 剪枝**。LoRA 不壓縮模型、不刪參數，是「**加**」一小組可訓練矩陣。
> 2. RAG 檢索階段最大的挑戰是「**語意相似但答非所問**」，不是選哪個向量資料庫套件。
> 3. ReAct 的 **Thought 不能拿掉**，那是推理過程；問題出在 Agent **沒呼叫工具查證**就直接回答。
> 4. 要比較**生成式 vs 鑑別式**模型的資料效率 → **逐步減少標註比例**（低資源實驗）。

## Notes
### 一、LLM 客製化：微調、LoRA、Prompt Tuning
#### 115-1 Q2｜LoRA 的主要優勢
新創公司要對 Llama3 70B 做領域微調，但 GPU 記憶體不足以支撐完整反向傳播，希望凍結原權重、只訓練少量額外參數，評估採用 LoRA。LoRA 在此場景的主要優勢為何？
- (A) 透過知識蒸餾將 70B 模型壓縮為較小的學生模型
- (B) 對原始模型各層權重進行剪枝，移除低重要性參數後再微調
- (C) 凍結原始預訓練權重，僅在各層加入低秩分解的可訓練矩陣，大幅降低可訓練參數量與 GPU 記憶體需求
- (D) 將注意力機制改為稀疏注意力，以降低長序列計算成本

> [!success]- 點開看答案
> **答案：C**
>
> LoRA 的想法：權重的「**變化量**」其實不需要那麼多自由度，所以用兩個很瘦的矩陣 A×B（低秩）來近似它。70B 模型本體不動，只訓練這兩個小矩陣，可訓練參數常常**不到 1%**。
> (A) 蒸餾、(B) 剪枝、(D) 稀疏注意力都是**模型壓縮或加速**技術，不是 LoRA。
>
> **業界做法**：記憶體更吃緊時用 **QLoRA**（把凍結的原模型量化成 4-bit 再接 LoRA），單張消費級 GPU 就能微調大模型。

#### 115-1 Q13｜Prompt Tuning 與傳統微調的本質差異
公司評估兩方案客製化 LLM 客服：方案 A 為提示微調（在輸入端加入可學習的軟提示），方案 B 為傳統微調（以標註問答資料調整模型）。兩者最本質的技術差異為何？
- (A) 提示微調主要用於降低推論延遲，傳統微調則用於提升模型容量
- (B) 兩者技術本質相同，差別僅在於學習率設定不同
- (C) 傳統微調通常需要更新模型參數，提示微調主要透過調整輸入表示來影響模型行為
- (D) 兩者差異僅在於是否使用預訓練模型

> [!success]- 點開看答案
> **答案：C**
>
> **軟提示（Soft Prompt）**不是人看得懂的文字，而是一組放在輸入前面、可以被訓練的**向量**。模型本體完全凍結，只學這組向量。
> ⚠️ 注意區分：**Prompt Tuning（訓練向量）≠ Prompt Engineering（人工寫提示詞）**。

#### 115-1 Q14｜緩解災難性遺忘
通用 LLM 在醫療問答語料上做監督微調（SFT），發生災難性遺忘。在計算資源有限下，哪一種設計最能有效學習新任務並保留原有能力？
- (A) 凍結大部分預訓練參數，僅對少量新增模組（如 LoRA 層）微調，並控制更新範圍以減少對原有知識的干擾
- (B) 提高學習率並縮短訓練步數，使模型快速收斂至新任務
- (C) 僅使用醫療語料進行多輪訓練，強化模型對新任務的專注程度
- (D) 增加批次大小以穩定梯度更新

> [!success]- 點開看答案
> **答案：A**
>
> **災難性遺忘**＝學了新東西，舊的就忘了。原因是全量微調會改到所有權重。凍結原權重、只動 LoRA 這類小模組，舊知識就保留在沒被動到的地方。
> (B) 學習率越高，原權重被改得越兇，**更容易**遺忘。(C) 只餵醫療資料會讓遺忘更嚴重。
>
> **業界做法**：再搭配**混入少量通用資料**一起訓練（Replay／資料混合），是最便宜有效的組合。

### 二、RAG 與 AI Agent
#### 114-2 Q17｜RAG 檢索階段最關鍵的挑戰
要建立高效能 RAG 系統，在「**檢索階段**」最關鍵的挑戰為何？
- (A) 確保檢索到的文件能完整納入語言模型的上下文視窗
- (B) 選擇使用 Faiss 或 ScaNN 等近似最近鄰搜尋函式庫
- (C) 降低嵌入模型在高維空間中的計算成本與記憶體占用
- (D) 避免向量檢索結果僅具語意相似但與查詢意圖無實質關聯的情況

> [!success]- 點開看答案
> **答案：D**
>
> 向量檢索找的是「**字面語意相近**」，不一定是「**真正能回答問題**」的文件。例如問「A 產品的退貨規定」，可能撈回「B 產品的退貨規定」，看起來很像，但答錯了。
> (A) 是**生成階段**的問題；(B)(C) 是工程選型，不是最關鍵的挑戰。
>
> **業界做法**：**混合檢索**（向量＋BM25 關鍵字）＋ **Reranker 重新排序**＋**查詢改寫**，是目前 RAG 的標準配置。

#### 115-1 Q16｜ReAct Agent 設計問題
ReAct Agent 要回答「台灣目前最大的電動車充電站營運商是哪間公司，以及其充電樁總數」，可用工具：web_search、get_webpage、calculator、get_current_date。System Prompt 只寫「你是資料查詢助理、每次只能用一個工具、知道答案時直接輸出」。第一輪 Agent 輸出：「Thought：我已經知道市場概況，不需要搜尋。Action：無。Answer：XX 公司，500 個充電樁。」此設計有何問題、該如何改善？
- (A) System Prompt 未要求回答前使用工具驗證，導致直接依賴既有知識產生幻覺；應明確規定即時性問題需先執行 web_search
- (B) calculator 與 get_current_date 屬於多餘工具，可能增加選擇複雜度
- (C) Thought 步驟佔用過多 token，應移除，直接輸出 Action
- (D) 應在第一輪就呼叫所有可用工具並彙整結果

> [!success]- 點開看答案
> **答案：A**
>
> 「目前最大」是**即時性資訊**，模型訓練資料會過時。Agent 卻跳過工具、憑記憶回答，就是**幻覺**。改善方式是在 System Prompt 明確規定：**涉及時效或數字的問題，必須先查證並引用來源**。
> (C) 剛好相反：**Thought（推理）＋ Action（行動）＋ Observation（觀察）**的循環就是 ReAct 的核心，拿掉 Thought 就不是 ReAct 了。
> (B) get_current_date 對「目前」類問題其實很有用。

#### 115-1 Q15｜Multi-Agent 的容錯機制
Multi-Agent 系統由 Orchestrator Agent 分配任務，多個 Worker Agent 分別執行搜尋、寫程式、彙整。若 Orchestrator 發現某 Worker 回傳品質不符預期，從容錯與可靠性角度，哪一項機制最能確保任務正確完成？
- (A) 直接採用該 Worker 的輸出，避免重試造成延遲
- (B) Orchestrator 具備結果評估能力，對不合格結果觸發重試或重新分配給不同 Worker，並記錄失敗原因供後續改善
- (C) 強制所有 Worker 統一使用相同的 LLM
- (D) 任何一個 Worker 失敗時，整個任務直接中止

> [!success]- 點開看答案
> **答案：B**
>
> 可靠的 Agent 系統三件套：**評估（Evaluate）→ 重試／改派（Retry／Reroute）→ 記錄（Log）**。
> (D) 一個環節失敗就全部中止，等於沒有容錯。
>
> **PM 觀點**：Agent 上線前要定義清楚「**什麼叫做不合格**」（評估標準）、「**最多重試幾次**」（避免無限迴圈燒錢）、「**何時轉人工**」。

### 三、生成模型原理：GAN、VAE、Diffusion
#### 114-2 Q20｜GAN 模式崩潰的解法
使用 GAN 生成人臉影像時出現「模式崩潰（Mode Collapse）」，最常被用來有效解決的方法為何？
- (A) 在鑑別器中加入梯度懲罰以穩定訓練
- (B) 採用 Wasserstein 距離（WGAN 損失）替代原始 GAN 損失函數
- (C) 對生成器輸入的潛在向量加入隨機擾動
- (D) 使用多尺度鑑別器架構

> [!success]- 點開看答案
> **答案：B**
>
> **模式崩潰**＝生成器發現某幾張臉特別容易騙過鑑別器，就只生這幾張，多樣性消失。
> 原始 GAN 的損失函數在分布差很遠時梯度幾乎為零，生成器學不到方向；**WGAN** 改用 Wasserstein 距離，即使分布差很多也有有效的梯度，因此大幅緩解模式崩潰。
> (A) 梯度懲罰（WGAN-GP）是 WGAN 的**改良版**，用來讓訓練更穩定，題目問「最常用來解決模式崩潰」的根本方法，官方選 WGAN 損失。

#### 114-2 Q38｜Stable Diffusion 生成影像模糊
使用 Stable Diffusion 生成 4K 產品圖，發現邊緣與細節有顆粒化與模糊。只能在生成階段調整，希望提升清晰度與紋理且避免過度平滑，最適合的做法為何？
- (A) 降低取樣步數，以縮短生成時間
- (B) 增加取樣步數並選擇高品質取樣器，以強化細節還原度
- (C) 提高 CFG 值，使生成結果更具創意與多樣性
- (D) 改用低解析度輸入以降低計算成本

> [!success]- 點開看答案
> **答案：B**
>
> 擴散模型是「一步一步去除雜訊」來生成影像。步數太少，雜訊沒去乾淨，就會顆粒化；選擇好的取樣器（如 DPM++）可以在相同步數下還原更多細節。
> (C) 錯在 **CFG 越高＝越貼近提示詞（越不多樣）**，太高還會讓畫面過飽和、失真，描述剛好相反。
>
> **業界做法**：4K 圖通常先生成較低解析度，再用 **Hires.fix 或超解析度放大（Upscaler）** 補細節。

#### 114-2 Q40｜VAE、GAN、擴散模型的根本差異
哪一項最正確描述 VAE、GAN 與擴散模型在多模態潛在空間對齊與生成策略上的根本差異？
- (A) VAE 透過顯式潛在變數建模實現跨模態對齊，適合捕捉整體語意結構但生成解析度有限；GAN 透過對抗損失學習分佈映射，品質高但穩定性差；擴散模型以條件化去噪實現高保真跨模態生成，兼具穩定性與多樣性
- (B) VAE 與擴散模型均屬隱式生成架構，主要依賴對抗式訓練；GAN 則以顯式後驗估計提升一致性
- (C) VAE 與 GAN 均使用馬可夫鏈進行跨模態轉換；擴散模型則透過 KL 散度最小化學習語意對應
- (D) 三者皆依賴同一潛在表徵空間，僅在解碼器結構不同

> [!success]- 點開看答案
> **答案：A**
>
> | | VAE | GAN | 擴散模型 |
> |---|---|---|---|
> | 核心機制 | 編碼成機率分布再解碼 | 生成器 vs 鑑別器對抗 | 逐步加噪、再逐步去噪 |
> | 優點 | 穩定、潛在空間有結構 | 畫質銳利、生成快 | 畫質高、多樣、穩定 |
> | 缺點 | 影像偏模糊 | 難訓練、模式崩潰 | 生成慢（要很多步） |
>
> (B)(C) 把機制張冠李戴：用**對抗訓練**的是 **GAN**；用**馬可夫鏈**逐步加噪去噪的是**擴散模型**。

#### 114-2 Q9｜資料增強反而讓效能下降
訓練生成式 AI 模型時導入資料增強，但效能反而下降。最可能的原因與改善策略為何？
- (A) 增強樣本未經隨機初始化，導致梯度更新不穩定
- (B) 增強後資料的特徵分佈與原始資料不一致，影響泛化能力，應檢查並調整增強策略以維持語意一致性
- (C) 增強樣本比例過高，造成模型偏好，應適度**提高**增強比例並調整學習率
- (D) 增強後資料的標註可信度下降，應以半監督學習重新校正

> [!success]- 點開看答案
> **答案：B**
>
> 增強過頭，資料就「變質」了。例如把數字 6 旋轉 180 度變成 9、把醫療影像左右翻轉讓器官位置相反，模型學到的是錯的東西。
> (C) 前半句說比例過高，後半句卻說要「提高」比例，自相矛盾。
>
> **原則**：增強方式必須符合「**現實中真的可能發生的變化**」。

### 四、生成式 vs 鑑別式模型的選用
#### 114-2 Q42｜上線後資料分佈改變的應對
金融風控系統部署鑑別式模型（如 Transformer Classifier），上線後分類錯誤率上升，檢查發現輸入資料分佈已與訓練集明顯不同。最適合的應對策略為何？
- (A) 改用 GAN 生成新樣本並混入訓練集
- (B) 改用邏輯迴歸以提升穩定性
- (C) 增加模型容量，以學習更多樣本差異
- (D) 使用變分自編碼器（VAE）監控潛在空間分佈，偵測輸入資料偏移

> [!success]- 點開看答案
> **答案：D**
>
> VAE 學會了「**正常資料長什麼樣子**」，新資料丟進去，如果**重建誤差**變大或潛在向量落在陌生區域，就代表資料分布偏移了。這是生成式模型在鑑別式系統裡常見的「**輔助監控**」用法。
> (A)(B)(C) 都在「換模型」，但沒先偵測與確認偏移就換模型，是在亂槍打鳥。

#### 114-2 Q43｜比較生成式與鑑別式的資料效率
客服郵件分類（投訴、詢問、表揚），方案 A 為 VAE 建立潛在語意空間再接分類器（生成式），方案 B 為 BERT Classifier 直接監督式分類（鑑別式）。現有標註約 2,000 筆、擴充成本高。要公平比較兩者的**資料利用效率**與泛化能力，最能突顯本質差異的實驗設計為何？
- (A) 在完整資料集上分別訓練，比較 Accuracy 與推論時間
- (B) 在低資源情境下，逐步減少標註比例（100%、50%、10%），比較 F1-score
- (C) 使用 GAN 生成文本樣本補足資料，觀察精確率差異
- (D) 在相同資料上固定輸入維度，只調整參數量，比較過擬合敏感度

> [!success]- 點開看答案
> **答案：B**
>
> 「**資料利用效率**」＝在標註很少時還能表現多好。所以實驗要**刻意減少標註量**，畫出「標註比例 vs F1」曲線，看誰掉得比較慢。生成式方法可以利用沒標註的資料學習結構，通常在低資源時較有優勢。
> (A) 用完整資料比，看不出誰比較省資料。

#### 114-2 Q44｜同時要預測又要生成虛擬樣本
電信公司要預測顧客是否流失，並模擬不同促銷策略下的行為變化，**生成多樣化虛擬樣本**做 A/B 測試與策略評估。最適合的方法為何？
- (A) 傳統隨機森林
- (B) 邏輯迴歸
- (C) 變分自編碼器（VAE）或生成對抗網路（GAN）
- (D) 強化學習代理

> [!success]- 點開看答案
> **答案：C**
>
> 關鍵字是「**生成虛擬樣本**」，只有生成式模型做得到。隨機森林、邏輯迴歸都只能預測，不能生成資料。
>
> **業界做法**：表格資料的合成常用 **CTGAN、TVAE**（SDV 套件）；真正要估計「促銷策略的效果」，業界更常用 **Uplift Modeling（增益模型）**與因果推論。
